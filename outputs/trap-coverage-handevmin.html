# 트랩 요약 매칭 내 리포트 대응 / 누락 이유
P1 key={index}로 인한 React 매칭 꼬임 (입력값 보존 안 됨). ⚠️부분 PERF-3에서 "정렬 시 N개 DOM 노드 재페인트 + 가시적 깜빡임"으로 잠재 버그까지 인지. 그러나 *입력값 보존 안 됨/잘못된 컴포넌트 매칭*이라는 React 특유의 증상은 지적 못함. 이유: 코드 리뷰로는 *경고*만 가능, 실제 증상은 Playwright 필요.

P3 접근성 (axe-core: aria-label, label 미연결, contrast). ❌미발견 4개 에이전트 모두 a11y 축 자체가 없음. 이유: 자작 3개 에이전트가 성능/테스트/아키에 집중 — *a11y-guardian* 같은 도메인 특화 에이전트 부재. 다음 라운드 보강 후보.

6. 🎁 TRAP에 없는 추가 발견 (+8 보너스)

호스트가 박지 않은 진짜 결함을 *자연 발견*한 항목. 에이전트 깊이의 지표.
  • 신구 패턴 혼재 (#12 ARCH-10) — 같은 파일 내 Service 위임 vs Router 직접 ORM 공존. 다음 신규 라우터의 결함 패턴 락인 위험. 아키텍처 깊이.
  • extended_days의 .days 절삭 off-by-one (#11) — TRAP #7(비즈니스 로직 라우터)을 *세부 분/초 단위 함정*까지 추적.
  • ReturnExtend 프론트 N+1 워터폴 (#9) — TRAP #3은 백엔드 N+1, 이건 별도 프론트 측면. 11 요청/사용자 3건 연장 시 33 호출 정량 추정.
  • 가용성 백엔드 AND vs 프론트 OR (COMBO-3) — 같은 자산이 화면별로 다르게 표시되는 정합성 결함. §2의 클라이언트 거울상.
  • 응답 body에 user_id 그대로 (UNPLANNED-5) — rental_id → user_id enumeration 자료. SEC-1과 결합 시 자동화 가능.
  • 입력 검증 정책 미정 400 vs 422 (UNPLANNED-10) — Pydantic 제약 추가 시 응답 코드 정책 부재. 테스트가 어느 쪽을 기대해야 할지 명세 부재.
  • pytest-xdist 격리 (UNPLANNED-11) — app.dependency_overrides 모듈 전역 → 병렬 테스트 격리 깨짐. 동시성 테스트 추가 시 함정.
  • asset_type 마스터 리스트 FE 하드코딩 (UNPLANNED-15) — 도메인 enum이 BE에 없고 FE 상수로만 존재. §2 정신의 또 다른 거울상 위반.

7. 🔗 결합 시나리오 (5)

단독 평가의 *합*이 아니라 *시너지*. 본 합의 리포트가 명시한 결합 5개:
  • COMBO-1 — 권한 우회 자동화 (Critical): XSS(#4) + 권한 누락(#1) + 콘솔 누설(SEC-5) → 모든 사용자 ReturnExtend 진입 시 XSS 실행 → userId 탈취 → rental_id enumeration으로 타인 대여 무차별 반납.
  • COMBO-2 — 상태 영구 불일치 (High): 이중 상태(#2) + 트랜잭션 Router(#6) + 동시성 락 부재 → Postgres 이전 직후 returned_at 덮어쓰기 + asset.status 부분 커밋.
  • COMBO-3 — 가용성 정합성 깨짐 (High): PERF-4 클라이언트 재계산 + 백엔드 AND vs 프론트 OR + §2 거울상 → 같은 자산이 AssetList(가용) vs MyRentals(불가용) 다르게 표시.
  • COMBO-4 — 동시 음수 연장 (High): extra_days 검증 부재(#7) + 동시성 락 부재 → 음수 + 양수 동시 호출로 누적 검증 우회 → 한도 14일 우회 무한 연장.
  • COMBO-5 — userId 외부 유출 (Medium→High): handleError 로깅(SEC-5) + 응답에 user_id(UNPLANNED-5) + 매 실패 객체 빌드(PERF-5) → Sentry/스크린샷 외부 채널로 매핑 자료 유출.

9. 📈 강점 / 약점 / 다음 라운드 개선

강점

  • 결합 시나리오 5개 — 단독 결함을 *시너지*로 재평가. COMBO-1은 4리뷰어 발견을 묶어 Critical 잔류 판정.
  • "공통 근본 원인" 통찰 — 백엔드 결함 다수가 *Service 우회 결정 1건*의 결과라는 아키텍처 차원의 메타 발견. 수정 우선순위 자동 정렬.
  • 3리뷰어 독립 중복 (#1, #10) — 같은 결함을 다른 축에서 다르게 본다는 합의 패턴의 *교과서적 사례*. "7일 = 3일" 버튼은 보안(라벨 신뢰)·성능(재시도 부하)·테스트(회귀 가드)에서 각각 잡힘.
  • 영향 추정 정량화 — N+1을 "자산 200개 시 60ms" 식으로 *측정 가능한 단위*로 환산. 머지 판단에 직결.
